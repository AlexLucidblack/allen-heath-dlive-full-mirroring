# GitHub: загрузка, оформление и выпуск приложения

Пошаговая инструкция для Allen&heath Dlive v2.12 Full Mirroring, сборка 0.6.6. macOS и Windows. Редакция: 25 октября 2026.

> Результат: публичная страница проекта с оформленным README, документацией RU/EN, иллюстрациями и релизом, откуда читатель скачивает рабочий ZIP и инструкции. Эта инструкция не создаёт репозиторий автоматически.

## 1. Какие файлы скачать

Скачайте обновлённый Allen_heath_Dlive_v2.12_GitHub_Package.zip из сообщения в чате и распакуйте его. Здесь уже включены последние PDF, предупреждения об одинаковой сцене и картинки для статей.

Внутри внешней папки github_delivery находятся:

- repository — содержимое будущего репозитория: код, README.md, документация, иллюстрации, tests, tools и скрытая папка .github.
- release — готовый ZIP приложения, два PDF, RELEASE_NOTES.md и SHA256SUMS.txt.
- START_HERE.md — краткое описание комплекта.

На GitHub загружается содержимое repository. ZIP из release прикладывается к релизу. Весь внешний архив в корень репозитория загружать не нужно: иначе исходники и оформление останутся спрятанными внутри архива.

Рабочий архив приложения предназначен сразу для обеих ОС: в нём есть .command для macOS и .bat для Windows. Это Python-приложение; готовых установщиков .app/.exe в комплекте нет.

## 2. Подготовьте аккаунт и название

1. Откройте https://github.com/ и войдите в свой аккаунт. Если аккаунта нет, пройдите Sign up и подтвердите почту.
2. Используйте компьютер: перетаскивать папки и проверять структуру на нём удобнее, чем на телефоне.
3. Название репозитория: allen-heath-dlive-full-mirroring.
4. Полное название приложения в README остаётся Allen&heath Dlive v2.12 Full Mirroring. В адресе репозитория используем короткое имя латиницей.
5. В Description можно вставить: Independent active/standby control mirroring for two dLive systems. Python, macOS/Windows, AH-Net TCP/UDP.

Приложение имеет сборку 0.6.6; v2.12 в названии относится к прошивке dLive. Не называйте релиз приложения v2.12, если публикуете эту сборку.

## 3. Создайте пустой репозиторий

1. В верхней части GitHub нажмите «+» → New repository.
2. В Owner выберите свой аккаунт; в Repository name введите allen-heath-dlive-full-mirroring.
3. Добавьте Description из предыдущего пункта.
4. Выберите Public, если проект должен открываться читателям без приглашений. Private подходит для подготовки, но ссылки на его файлы не станут общедоступными.
5. Не включайте автоматическое создание README, .gitignore и LICENSE: README и .gitignore уже подготовлены. Лицензию не назначайте случайным выбором.
6. Нажмите Create repository.

Лицензия в комплекте не выбрана: об этом сообщает LICENSE_STATUS.md. Определите свои условия распространения и правообладателя отдельно. Публикация исходников сама по себе не означает выдачу лицензии MIT/GPL. Это не техническое препятствие для черновой загрузки файлов.

## 4. Загрузите исходники через браузер

1. На пустой странице репозитория найдите ссылку uploading an existing file. В непустом репозитории используйте Add file → Upload files.
2. Откройте на компьютере папку repository. Нужно перетащить её содержимое, а не саму папку repository и не внешний ZIP.
3. Покажите скрытые файлы. В macOS в Finder нажмите Command + Shift + точка. В Windows в Проводнике включите «Вид → Показать → Скрытые элементы»; название зависит от версии ОС.
4. Перетащите файлы и папки на страницу загрузки, сохраняя структуру. Особенно проверьте .github, .gitignore и .gitattributes.
5. Если загружаете частями, переносите целые группы. В браузере одновременно допускается до 100 файлов; большие группы разделите. Для данного комплекта лимит размера отдельного файла 25 МиБ не мешает.
6. Дождитесь завершения загрузки всех выбранных файлов.
7. Напишите сообщение коммита: Add dLive Full Mirroring 0.6.6.
8. В своём новом репозитории можно сохранить прямо в main, если это разрешено. Если интерфейс предлагает новую ветку и Propose changes, создайте её, затем откройте предложенный Pull request и выполните Merge после проверки списка файлов. Кнопка сохранения может называться Commit changes или Propose changes в зависимости от выбранного пути.

Проверка результата: в корне GitHub должны быть README.md, allen_heath_dlive_full_mirroring.py и папки docs, tests, tools, .github. Если первым уровнем оказалась только папка repository, структура вложена лишний раз: перенесите её содержимое в корень до создания релиза.

## 5. Проверьте внешний вид

1. Откройте вкладку Code. Ниже списка файлов должен отображаться README с обложкой.
2. Проверьте схему подключения и иллюстрацию интерфейса; изображения должны открываться.
3. Найдите красное предупреждение: перед подключением загрузить одну и ту же сцену на оба пульта.
4. Нажмите English и вернитесь через Русский. Затем откройте PDF-инструкции, возможности и устранение ошибок.
5. Не меняйте имена каталогов docs/assets без обновления ссылок в README: картинки и документация используют относительные пути.
6. Если хотите изменить текст, откройте README.md → значок карандаша → Edit. Проверьте вкладку Preview, затем сохраните коммит. Если файл не редактируется в вашем представлении, используйте меню файла или откройте его в веб-редакторе GitHub.

README.md — основной русский вход. README.en.md — английская страница проекта. README_RU.md и README_EN.md — инструкции, включаемые в компактный рабочий архив; не удаляйте их как дубли.

## 6. Добавьте описание, темы и обложку ссылки

1. Справа от списка файлов в блоке About нажмите шестерёнку. Сохраните Description, если он ещё не заполнен.
2. Добавьте Topics: allen-heath, dlive, audio, mixing-console, redundancy, python, macos, windows.
3. Поле Website пока можно оставить пустым. Позже вставьте ссылку на основную статью Telegra.ph, когда она будет опубликована.
4. Откройте Settings репозитория. В разделе General найдите Social preview → Edit → Upload an image.
5. Выберите repository/docs/assets/social-preview.png из распакованного комплекта.
6. Вернитесь к Code. Обложка README и Social preview — разные изображения с разными задачами. Изменение Social preview не заменяет картинку внутри README.

Наличие обложки не гарантирует немедленное обновление старого предпросмотра Telegram: клиенты могут сохранять ранее полученные данные. После публикации проверьте новую ссылку в нужном канале.

## 7. Проверьте Actions

1. Откройте вкладку Actions.
2. Если GitHub предлагает разрешить workflows именно для вашего репозитория, ознакомьтесь с уведомлением и включите их при необходимости.
3. Откройте запуск workflow tests после загрузки файлов. Дождитесь результата отдельных jobs.
4. Зелёный результат означает успешное прохождение указанных проверок. Красный требует открыть ошибочный шаг и прочитать сообщение. Отсутствие запуска не считается успешной проверкой: проверьте наличие .github/workflows/tests.yml и разрешения Actions.
5. Не заменяйте в описании «проверено локально» на «проверено GitHub Actions», пока удалённый запуск действительно не завершился.

Тесты используют имитаторы и не видят реальные пульты. Доступность всех моделей на железе и аудиорезерв ими не подтверждаются. Браузерная загрузка также не сохраняет Unix-право выполнения .command; при необходимости пользователь выдаёт его через chmod, как описано в руководстве. Готовый runtime ZIP сохраняет нужные атрибуты отдельно.

## 8. Создайте Release для скачивания

1. Вернитесь на Code → Releases → Draft a new release / Create a new release.
2. Откройте Choose a tag. Введите v0.6.6 и выберите создание нового тега. Target — main с загруженными файлами.
3. Release title: Allen&heath Dlive v2.12 Full Mirroring — 0.6.6.
4. В описание вставьте содержимое release/RELEASE_NOTES.md. Сохраните различие между сборкой приложения и целевой прошивкой.
5. В область прикрепления файлов добавьте четыре файла из release: Allen_heath_Dlive_v2.12_Full_Mirroring_0.6.6.zip, USER_GUIDE_RU.pdf, USER_GUIDE_EN.pdf и SHA256SUMS.txt.
6. Не прикладывайте весь GitHub_Package.zip вместо рабочего архива. Автоматические Source code (zip/tar.gz) — исходники, а не специально подготовленный компактный пакет пользователя.
7. Сначала используйте Save draft. Проверьте вложения, текст, условия распространения и выбранный тег.
8. Когда всё готово к открытой публикации, нажмите Publish release. Не помечайте сборку как предварительную только ради оформления; отметку Pre-release используйте, если сознательно хотите сообщить о предварительном статусе.
9. Откройте опубликованный релиз и скачайте рабочий ZIP и оба PDF самостоятельно.

Проверяйте файлы до окончательной публикации: в репозитории с immutable releases после публикации редактирование вложений ограничено. Изменение только документации в этом комплекте не меняет номер сборки кода.

## 9. Скопируйте правильные ссылки

1. Сохраните адрес репозитория из адресной строки.
2. Сохраните адрес страницы конкретного релиза v0.6.6 — его удобно ставить в статье как «Скачать приложение».
3. В Assets щёлкните правой кнопкой по runtime ZIP → Copy link address. Повторите для обоих PDF.
4. Для простого перехода на последнюю подходящую публикацию можно использовать страницу Releases. Прямые ссылки на вложения конкретного релиза сохраняют привязку к этой сборке.
5. Откройте полученные адреса в приватном окне без входа в GitHub. Читатель должен видеть страницу и скачивать файлы.

Не используйте в публичной статье sandbox:-ссылки из чата, ссылки на личные файлы ChatGPT или адрес локального диска. YOUR_ACCOUNT в примерах означает ваш реальный логин; не оставляйте такую метку в опубликованном тексте.

## 11. Дополнительный вариант: через Git

Этот путь пригодится, если браузер не переносит папки. Используйте его вместо первичной браузерной загрузки в пустой репозиторий, а не поверх уже независимо созданной истории.

Откройте Terminal на macOS или Git Bash на Windows, перейдите в repository. Выполняйте команды по одной:

~~~
git init -b main
git add .
git status --short
git commit -m "Publish dLive Full Mirroring 0.6.6"
git remote add origin https://github.com/YOUR_ACCOUNT/allen-heath-dlive-full-mirroring.git
git push -u origin main
~~~

Перед remote замените YOUR_ACCOUNT своим логином. Git должен быть установлен. Если Git попросит имя и email автора, настройте их для этого репозитория; можно использовать адрес noreply из настроек GitHub. Вход по HTTPS выполняйте поддерживаемым способом GitHub — обычный пароль аккаунта не используется как пароль Git. Не вставляйте токен в текст remote или в публичные файлы. Если вы уже загрузили проект другим способом, сначала клонируйте существующий репозиторий и переносите изменения в его рабочую копию.

## 12. Обновления после публикации

Для исправления текста отредактируйте файл и сделайте новый коммит. Для обновления кода используйте новую сборку и новый тег, не перезаписывайте старый релиз ради скрытой замены программы. Обновляйте README, оба языка, PDF и контрольные суммы согласованно. Если меняется только документация, явно напишите это в описании публикации.

Никогда не загружайте рабочие connection.json, logs, PCAP/PCAPNG, дампы, пароли и приватные диагностики. Подготовленный комплект исключает эти данные; при добавлении собственных файлов проверяйте их отдельно.
