# Руководство пользователя
## Allen&heath Dlive v2.12 Full Mirroring

Сборка приложения 0.6.6. Целевая прошивка dLive: 2.12 Rev. 94091. Приложение запускается на одном компьютере Windows или macOS и управляет двумя независимыми системами Surface + MixRack.

![Схема подключения](assets/network.png)

> [!CAUTION]
> **ВАЖНО: перед подключением приложения загрузите одну и ту же сцену на оба пульта.** Mirror передаёт последующие изменения и не выравнивает исходное состояние автоматически. При различиях I/O проверьте соответствие портов и назначений; 48V задаётся отдельно на каждой системе.

## 1. Что именно делает приложение

Mirror получает изменения от текущего мастера и отправляет соответствующие команды второй системе. Для известных объектов программа находит адрес назначения по имени, поэтому числовые адреса из одной сессии не используются как постоянные адреса другой.

Это передача событий управления. При первом подключении программа не делает полный снимок всех значений и не приводит автоматически все настройки второй системы к первой. До запуска подготовьте совместимые исходные конфигурации обоих пультов штатным способом. Различия в числе физических входов/выходов и назначениях каналов нужно учитывать заранее.

У каждой Surface остаётся её собственный MixRack. Mirror не переносит звук по TCP/UDP, не заменяет gigaACE и не коммутирует аудиовыходы при отказе.

## 2. Комплект и требования

Нужны две Surface, два MixRack, компьютер с Python 3.10+ и доступностью всех четырёх IP-адресов. Сторонние Python-пакеты для запуска не нужны.

Для приведённой схемы используйте два Ethernet-интерфейса компьютера: встроенные, USB-C/Thunderbolt-адаптеры или подходящие сетевые карты. Два IP в интерфейсе программы не создают сетевые адаптеры и не назначают адреса автоматически. Один интерфейс с дополнительными IP или VLAN возможен только при правильно настроенной внешней сети; эта инструкция использует два интерфейса, чтобы маршрут к каждой системе был однозначным.

Папка программы должна быть доступна для записи: в ней сохраняется connection.json, а при подключении/обрыве создаётся logs. Не запускайте исходники прямо из ZIP. Окно терминала или командной строки должно оставаться открытым во время работы.

| Компонент | Требование |
|---|---|
| Python | 3.10 или новее; интерпретатор с sqlite3 |
| Браузер | Современный браузер с JavaScript |
| Компьютер | Доступ к четырём адресам и два локальных адреса для выбранной схемы |
| dLive | Основная проверенная конфигурация — прошивка 2.12 Rev. 94091 |
| Установка | Исходники Python с .command/.bat, без отдельного .app/.exe |
| Интернет | Нужен для получения Python/файлов, не нужен для локального зеркалирования |

Точный минимум версии ОС и аппаратных ресурсов не измерялся. Совместимость ОС зависит также от выбранного выпуска Python; наличие запуска не заменяет проверку с вашим оборудованием.

## 3. Сетевая схема и адреса

| Узел | Система 1 / A | Система 2 / B |
|---|---|---|
| Surface | S5000, 192.168.1.71 | C3500, 192.168.2.71 |
| MixRack | DM64, 192.168.1.70 | DM64, 192.168.2.70 |
| Адрес компьютера | 192.168.1.200 | 192.168.2.200 |
| Маска | 255.255.255.0 | 255.255.255.0 |
| TCP / UDP устройств | 51321 / 51327 | 51321 / 51327 |

Адреса приведены как пример. Каждый адрес должен быть уникальным в своей сети. В конфигурации приложения четыре адреса Surface/MixRack должны различаться.

1. Соедините Surface 1 со своим MixRack 1 через gigaACE.
2. Соедините Surface 2 со своим MixRack 2 через gigaACE.
3. Подключите первый Ethernet компьютера к Network Control системы 1.
4. Подключите второй Ethernet компьютера к Network Control системы 2.
5. Назначьте адреса компьютеру в ОС по инструкциям Windows/macOS.
6. Проверьте доступность каждого MixRack и каждой Surface.

Не подключайте обычный Ethernet-порт компьютера к gigaACE как к сетевому адаптеру управления. IP-доступ к Surface должен быть доступен через выбранную сеть управления; одного ответа MixRack недостаточно.

Шлюз и DNS на изолированных интерфейсах прямого управления обычно не нужны. Не переносите настройки домашней сети на оба адаптера; при наличии маршрутизаторов используйте настройки вашей сетевой схемы.

## 4. Установка

> [!CAUTION]
> **Перед подключением: загрузите одинаковые сцены на обоих пультах.** Только после этого подключайте Mirror и запускайте передачу.

Все действия приведены здесь полностью. Открывать отдельные файлы инструкции или нажимать кнопки перехода для установки не требуется. Нужен Python 3.10+; дополнительные пакеты через pip для запуска не нужны.

### Установка в Windows

#### Python и файлы

1. Откройте https://www.python.org/downloads/windows/ и установите CPython 3.10 или новее. Если выбран классический установщик, запустите его, включите добавление Python в PATH и выполните Install Now. Если установлен Python Install Manager, откройте PowerShell и установите runtime командой py install 3.12 (3.12 — пример совместимой версии). Дождитесь окончания установки.
2. Откройте новое окно PowerShell и проверьте команду:

~~~powershell
py -3 --version
~~~

Если py отсутствует, проверьте python --version. Версия должна быть 3.10 или новее. Если обе команды не работают, перезапустите PowerShell и проверьте установку Python; дальнейший запуск приложения пока невозможен.

3. Распакуйте рабочий архив, например в C:\DliveMirror. Не запускайте .bat из окна архиватора. Папка должна быть доступна текущему пользователю для записи.
4. Сохраните все файлы приложения рядом друг с другом. pip install для запуска не требуется.

#### Два сетевых интерфейса

Подключите Ethernet 1 к Network Control первой системы, Ethernet 2 — ко второй. Для примера из руководства:

| Интерфейс | IPv4 | Маска | Шлюз/DNS для изолированной линии |
|---|---|---|---|
| Ethernet 1 | 192.168.1.200 | 255.255.255.0 | Не задаются без необходимости схемы |
| Ethernet 2 | 192.168.2.200 | 255.255.255.0 | Не задаются без необходимости схемы |

В Windows откройте Параметры → Сеть и Интернет → Ethernet → нужный интерфейс → Назначение IP → Изменить → Вручную → IPv4. Введите адрес и маску; в некоторых версиях Windows вместо маски используется длина префикса 24. Названия разделов зависят от выпуска Windows.

Убедитесь, что меняете именно тот адаптер, кабель которого идёт к соответствующей системе. Настройки компьютера не изменяют IP пульта.

Проверка:

~~~powershell
ipconfig
ping 192.168.1.70
ping 192.168.1.71
ping 192.168.2.70
ping 192.168.2.71
Test-NetConnection 192.168.1.70 -Port 51321
Test-NetConnection 192.168.1.71 -Port 51321
Test-NetConnection 192.168.2.70 -Port 51321
Test-NetConnection 192.168.2.71 -Port 51321
~~~

Test-NetConnection проверяет TCP, не полноценную AH-Net-сессию и не UDP. Отсутствие ping не всегда означает отказ приложения: ICMP может быть отфильтрован. Но до запуска всё оборудование должно быть доступно по нужным адресам и портам.

Если Windows показывает запрос брандмауэра, разрешите используемому Python работу в доверенной сети управления. Не отключайте брандмауэр целиком. Нужны TCP/UDP-обмен с устройствами и приём ответов UDP на локальный динамический порт. Интерфейс браузера использует только 127.0.0.1.

#### Запуск

Дважды щёлкните Allen_heath_Dlive_v2.12_Full_Mirroring_Windows.bat. Окно останется открытым, а браузер откроет локальный интерфейс.

Или в PowerShell:

~~~powershell
cd C:\DliveMirror
py -3 allen_heath_dlive_full_mirroring.py
~~~

Если работает только python:

~~~powershell
python allen_heath_dlive_full_mirroring.py
~~~

В поле «IP компьютера → A/B» введите локальные адреса Windows-компьютера — 192.168.1.200 и 192.168.2.200 для этого примера.

Выберите модели, заполните IP Surface/MixRack, оставьте стандартные порты при обычной схеме, выберите начальное направление. Нажмите подключение, дождитесь готовности, затем запуск передачи.

#### Завершение и типовые проблемы

Не закрывайте окно .bat во время зеркалирования. Для планового завершения дождитесь пустой очереди, скачайте нужную диагностику и нажмите «Отключить оба»: все логи и незавершённые команды удаляются напрямую.

| Симптом | Проверка |
|---|---|
| py/python не найден | Откройте новое окно после установки; проверьте официальный способ установки и PATH |
| Вместо Python открывается магазин | Python runtime не установлен либо мешают execution aliases |
| Окно сразу закрывается | Запустите из PowerShell и прочитайте ошибку; проверьте наличие всех модулей и Python 3.10+ |
| WinError 10049 | Введённый локальный адрес не назначен адаптеру или адаптер отключён |
| TCP проходит, подписка нет | Проверьте UDP, брандмауэр, прошивку, адрес Surface и завершение загрузки оборудования |
| Address already in use | Укажите другой --ui-port либо завершите предыдущий экземпляр |
| Failed to fetch | Проверьте, что процесс Python жив и браузер открыт на текущем адресе |


### Установка в macOS

#### Python и файлы

1. Откройте https://www.python.org/downloads/macos/, выберите выпуск CPython 3.10 или новее и скачайте установщик macOS .pkg. Откройте .pkg двойным щелчком, пройдите «Продолжить» → согласие с условиями → «Установить», подтвердите установку паролем, если он запрошен, и дождитесь завершения. Официальные universal2-сборки предназначены для поддерживаемых Apple Silicon и Intel Mac; совместимость конкретного выпуска проверяется на странице Python.
2. Откройте Terminal и проверьте:

~~~sh
python3 --version
~~~

Наличие старого системного python3 не гарантирует подходящую версию. Не удаляйте и не заменяйте файлы системного Python Apple. Установка собственного Python с python.org выполняется отдельно.

3. Распакуйте приложение в доступную для записи папку, например Downloads или Documents. Не запускайте исходники прямо из ZIP.
4. Дополнительные библиотеки через pip не нужны.

#### Настройка двух Ethernet-подключений

Первый адаптер соедините с Network Control системы 1, второй — с системой 2. В macOS откройте Системные настройки → Сеть → нужный Ethernet/USB-адаптер → Подробнее → TCP/IP → Настроить IPv4 вручную.

| Интерфейс | IPv4 | Маска | Маршрутизатор/DNS |
|---|---|---|---|
| Первый Ethernet | 192.168.1.200 | 255.255.255.0 | Для изолированной линии обычно не нужны |
| Второй Ethernet | 192.168.2.200 | 255.255.255.0 | Для изолированной линии обычно не нужны |

Укажите настройки, соответствующие реальным адресам оборудования. Для другой сетевой схемы таблицу нужно изменить. Переименование сетевых служб для удобства допустимо, но само по себе не задаёт IP.

Для проверки используйте:

~~~sh
ifconfig
ping -c 3 192.168.1.70
ping -c 3 192.168.1.71
ping -c 3 192.168.2.70
ping -c 3 192.168.2.71
nc -vz 192.168.1.70 51321
nc -vz 192.168.1.71 51321
nc -vz 192.168.2.70 51321
nc -vz 192.168.2.71 51321
~~~

nc проверяет только TCP-порт. Mirror дополнительно использует UDP и регистрацию AH-Net. Ответ одного MixRack не подтверждает готовность всей системы Surface + MixRack.

#### Запуск через Finder

Первый запуск скачанного файла может блокироваться защитой Gatekeeper. Текущая поставка содержит Python-код и файл .command; это не подписанное и нотарифицированное Apple приложение .app. Установка официального Python не подписывает автоматически файл запуска Mirror.

##### Первый запуск: разрешение Gatekeeper

1. Установите Python и распакуйте весь комплект, как описано выше. Проверьте, что архив получен из доверенного источника.
2. В Finder откройте папку приложения и дважды щёлкните Allen_heath_Dlive_v2.12_Full_Mirroring.command.
3. Если macOS сообщает, что разработчик неизвестен или Apple не может проверить файл, закройте это предупреждение. Пока программа может не запуститься.
4. Откройте меню Apple → «Системные настройки» → «Конфиденциальность и безопасность».
5. Прокрутите до раздела «Безопасность» и найдите сообщение о блокировке именно файла Mirror.
6. Нажмите «Все равно открыть» / «Открыть в любом случае» (Open Anyway). Название кнопки зависит от версии и языка macOS.
7. Подтвердите действие паролем или Touch ID, если система запросит, затем нажмите «Открыть» в повторном предупреждении.
8. Должны открыться Terminal и локальная страница Mirror. Если браузер не открылся, используйте адрес из Terminal, обычно http://127.0.0.1:8780.

Разрешение относится к выбранному файлу. Последующие запуски этой копии обычно выполняются двойным щелчком. После загрузки обновления или другой копии подтверждение может понадобиться снова.

##### Если кнопки разрешения нет

Сначала ещё раз попробуйте открыть .command в Finder, затем вернитесь в настройки: сообщение появляется после попытки запуска. Проверьте, что разрешаете именно нужный файл. На управляемом организацией Mac исключение может быть недоступно — обратитесь к администратору.

Предупреждение о неизвестном разработчике отличается от сообщения об обнаруженном вредоносном ПО или повреждении файла. Во втором случае не используйте эту процедуру автоматически: проверьте источник и загрузку.

Глобально отключать Gatekeeper или разрешать все приложения для работы Mirror не требуется. Официальное описание процедуры Apple: https://support.apple.com/ru-ru/102445.

##### Если потерялось право на выполнение

Если после копирования потерялось разрешение на выполнение, откройте Terminal в папке приложения и выполните:

~~~sh
chmod +x Allen_heath_Dlive_v2.12_Full_Mirroring.command
./Allen_heath_Dlive_v2.12_Full_Mirroring.command
~~~

chmod +x задаёт право выполнения конкретного файла и не является подписью или подтверждением Apple. Это исправление Permission denied, а не замена процедуры Gatekeeper выше.

При запросе разрешений macOS разрешите программе доступ к локальной сети, если такая настройка доступна в вашей версии ОС. Не отключайте системные защиты целиком.

#### Запуск напрямую из Terminal

В Terminal наберите cd и пробел, перетащите распакованную папку приложения в окно и нажмите Return. Затем:

~~~sh
python3 allen_heath_dlive_full_mirroring.py
~~~

Если браузер не открылся, введите напечатанный адрес вручную, обычно http://127.0.0.1:8780. Программа не поставляется как подписанное .app; запуск через Python — штатный способ.

Введите все адреса и модели, выберите начального мастера, нажмите подключение и дождитесь готовности обеих систем. Затем включите передачу. Terminal должен оставаться открытым.

#### Сон, питание и завершение

Компьютер должен оставаться включённым, сетевые адаптеры — активными. Сон компьютера, выключение адаптера и закрытие процесса Python прерывают управление. Это не механизм автономного резервирования без компьютера.

Для завершения дождитесь пустой очереди, скачайте нужную диагностику, нажмите «Отключить оба», затем завершите процесс. Эта кнопка удаляет логи и незавершённые команды без корзины.

| Ошибка | Что проверить |
|---|---|
| Неизвестный разработчик / Apple не может проверить файл | Выполните первый запуск и разрешение для конкретного .command по процедуре выше |
| Кнопки «Все равно открыть» нет | Повторите попытку в Finder и откройте настройки; на управляемом Mac обратитесь к администратору |
| Permission denied у .command | Разрешение на выполнение; при необходимости запускайте Python напрямую |
| Can't assign requested address / Errno 49 | Локальный IP не назначен выбранному адаптеру либо адрес исчез при отключении |
| Connection refused | Адрес/порт и готовность службы пульта; временный отказ UDP теперь повторяется без закрытия живого TCP |
| Не найден модуль | Все файлы должны оставаться в одной папке; запускайте основной файл, не вспомогательные модули |
| Браузер не видит приложение | Процесс Python должен работать; проверьте порт и текущий URL |

Сначала проверяйте реальный адрес и маршрут, а затем параметры Mirror. Введение IP в поле программы не назначает его адаптеру macOS.


Запускается один и тот же Python-код с одинаковыми функциями. Различаются способ установки Python, имя файла запуска, команды диагностики сети и сетевые настройки ОС. Готовые подписанные установщики, автоматический системный сервис и фоновый агент не входят в комплект.

## 5. Интерфейс и поля

В шапке приложения выберите язык: «Русский» или English. Выбор запоминается в этом браузере для текущего адреса интерфейса. Переключение доступно при подключённых устройствах и не меняет адреса, направление, мастера или очередь. Если браузер запрещает локальное сохранение, язык работает до перезагрузки страницы. Диагностика сохраняет исходные технические коды.

Иллюстрация подготовлена по текущей разметке интерфейса с примерной адресацией; аппаратные соединения не изображаются как установленные.

| Модель MixRack | DM32/48/64 или CDM32/48/64 |

| TCP-порт | По умолчанию 51321 для MixRack |
| UDP-порт | По умолчанию 51327 для MixRack |
| IP компьютера → A/B | Локальный IP текущего компьютера, в том числе если это Windows |
| Начальное направление | Только 1 → 2 или 2 → 1 |
| Верхний индикатор | Текущий мастер и действующее направление, а не только первоначальный выбор |
| Очередь | Незавершённые отправки, включая неопределённые |
| Журнал | Основные события и ошибки; полный поток кадров в таблицу не выводится |

В полях «IP компьютера» на Windows и macOS вводятся локальные адреса текущего компьютера. Имя компьютера, внешний IP и адрес роутера в эти поля не подходят. Пустое поле допускает выбор ОС, но для двух сетей лучше явно указать оба локальных адреса.

В пользовательском интерфейсе отсутствуют выключатели рабочих опций и выбор профиля подписки. Максимальный профиль и автоматический резерв включены постоянно.

## 6. Первый запуск передачи

1. Запустите соответствующий файл .command или .bat. Если браузер не открылся, откройте вручную адрес из терминала, обычно http://127.0.0.1:8780.
2. Заполните карточки обеих систем и выберите начального мастера.
3. Нажмите «1. Подключить оба MixRack». Программа также начинает отдельные подключения к обеим Surface.
4. Дождитесь готовности обеих систем. ACK, ping и открытый TCP сами по себе ещё не означают завершение подписок.
5. Нажмите «2. Запустить передачу».
6. Измените на мастере один фейдер, Mute и тестовый параметр. Проверьте фактическое значение на второй системе.
7. Проверьте Global Tempo и нужные изменения Strip Assign.

Начать резервирование технически можно при полной готовности хотя бы одной системы. Для планового запуска лучше дождаться обеих: так вы проверите и направление, и исходную доступность резерва.

Не закрывайте терминал. Закрытие вкладки браузера само по себе обычно не останавливает сервер Python; завершение процесса Python останавливает приложение.

## 7. Обычная работа

Команды идут только от текущего мастера. Изменения на резервной системе не являются вторым независимым потоком управления. Выбирать «в обе стороны» не нужно и невозможно через этот интерфейс.

Распознанные уведомления преобразуются в команды записи, адреса подписанных объектов сопоставляются по имени. Антиэхо предотвращает возврат собственных записей в бесконечный цикл. Служебные ответы остаются в своих сессиях; известный поток измерений и системный журнал отфильтрованы. Каталог не является автоматическим обнаружением всех объектов любой прошивки.

Global Tempo передаётся отдельной командой периода в миллисекундах; текущее значение мастера дополнительно читается примерно каждые 250 мс. Первое и неизменившиеся значения повторных записей не создают. Эффекты, которые должны следовать общему BPM, настройте на Global Tap.

Strip Assign переносит изменения позиции внутри слоя с учётом ширины левого, среднего и правого банков. Если размеры Surface различаются, нельзя ожидать одинакового физического расположения всех фейдеров. Непомещающиеся позиции отмечаются в журнале; изменение геометрии банка требует новой сессии.

## 8. Что происходит при обрыве

Если ведущая система теряет готовность, исправная полностью готовая система становится мастером. Проверяется состояние Surface и MixRack, а не только ping. При отказе одной Surface живую сессию MixRack сохраняют; при отказе одного MixRack сохраняют живую сессию Surface.

Сразу после отказа изменения оставшегося мастера записываются в очередь на диске. Автоподключение повторяется; полная загрузка пульта и его сетевых служб может занять больше времени, чем появление ответа ping. Временный отказ UDP у вернувшейся Surface не завершает уже живую TCP-сессию.

| Этап | Мастер | Направление |
|---|---|---|
| Старт 1 → 2 | Система 1 | 1 → 2 |
| Потеря системы 1 | Система 2, если готова | 2 → 1 |
| Возврат системы 1 | Система 2 | Восстановление в 1 |
| Восстановление завершено | Система 2 | 2 → 1 |
| Позже потеря системы 2 | Система 1, если готова | 1 → 2 |

После возврата старого мастера управление автоматически ему не возвращается. Чтобы планово назначить другой первоначальный мастер, сначала дождитесь опустошения очереди, остановите/отключите обе системы, выберите направление и подключитесь заново.

Если обе системы стали недоступны, автоматическое разрешение конфликта не выполняется: после восстановления оборудования требуется явный новый запуск передачи. Старая очередь после перезапуска процесса автоматически не продолжается.

## 9. Восстановление очереди и скорость

При возвращении назначения программа заново обнаруживает имена объектов и использует свежие адреса сессии. Нужные очереди объекты получают приоритет; известные записи могут идти до завершения полного каталога, хотя право стать мастером требует полной готовности.

Очередь отправляется группами до 32 команд и 32 КиБ с ограничением 1000 команд/с. Это ограничитель, а не гарантированная аппаратная скорость. Время восстановления зависит от доступности устройств, количества разных действий и сети.

Повторные абсолютные значения распознанных входных фейдеров и Mute сокращаются между другими действиями. Вместо проигрывания всех промежуточных движений восстанавливается последнее значение. FX, Global Tempo, раскладки и неизвестные команды этим правилом не уплотняются.

Порядок — порядок получения приложением. Независимые TCP и UDP не имеют общего аппаратного счётчика. При частичной отправке и обрыве запись состояния может повториться. Применение каждой обычной команды прошивкой не подтверждается отдельной проверкой.

Лимиты очереди: 250000 записей или 128 МиБ незавершённых данных. Переполнение, неопределённая отправка или непрозрачный пакет после смены сессии могут остановить восстановление. Это не повод удалять очередь вручную: сначала скачайте диагностику.

## 10. Логи и очистка

После полного восстановления двух систем и завершения всех незавершённых очередей дисковые логи удаляются напрямую, без корзины. Очистка также выполняется после первого запуска передачи, когда обе системы готовы и очередь пуста.

При исправной связи небольшой журнал событий и рабочая очередь находятся в памяти. При новом обрыве запись на диск возобновляется. Накопление полного трафика при нормальной работе прекращается. Успешная отправка в данном условии означает принятие записи сетевым сокетом, а не отдельное подтверждение прошивкой каждого параметра.

Автоматическая очистка не срабатывает при незавершённых, заблокированных или неопределённых командах, включая старую остановленную очередь текущего процесса. Файлы программы, connection.json и уже скачанные пользовательские копии не удаляются.

«Отключить оба» явно удаляет все логи приложения и все незавершённые очереди. Восстановить отброшенные изменения через программу нельзя. Если файл занят другой программой, ошибка удаления показывается в диагностике; при автоматической очистке будет повторная попытка.

Не удаляйте файлы SQLite/WAL/SHM вручную во время записи.

## 11. Кнопки остановки и завершение работы

| Действие | Результат |
|---|---|
| Остановить передачу | Останавливает зеркалирование и авто резерв; соединения остаются, автоматическое продолжение очереди не обещается |
| Отключить оба | Останавливает, закрывает соединения, удаляет дисковые логи и незавершённые очереди |
| Закрыть окно Python / Ctrl+C | Завершает процесс; штатное завершение вызывает отключение и очистку |
| Закрыть только вкладку | Сервер может продолжать работать в терминале |
| Перезагрузка/аварийный выход | Автоматическое продолжение прежней очереди после нового запуска не реализовано |

Для окончания работы сначала убедитесь, что нужные изменения применены и очередь пуста, скачайте необходимые данные, затем нажмите «Отключить оба» и завершите окно Python.

## 12. Как проверить систему перед использованием

Проведите один полный цикл до работы с аудио:

1. Проверьте все четыре IP и оба локальных адреса компьютера.
2. Запустите 1 → 2 и проверьте фейдер, Mute, тестовые DSP-параметры, Global Tempo и Strip Assign.
3. Убедитесь, что 48V остаётся локальным.
4. Отключите только S5000. Проверьте, что C3500 стала мастером.
5. На C3500 измените несколько параметров. Верните S5000 и проверьте восстановленные значения и новые действия после восстановления.
6. Убедитесь, что очередь пуста, а дисковые логи удалены.
7. Повторите сценарий для другой системы и для потери MixRack.
8. Проверку реального аудиорезерва проведите отдельно: приложение не меняет маршруты звука автоматически.

## 13. Файлы, обновление и диагностика

Все Python-модули и JSON-каталоги рабочей поставки нужны приложению. Файл scene_sync.py остаётся зависимостью протокольных структур, хотя перенос сцен отключён. Не удаляйте его как «лишний».

При обновлении остановите предыдущую версию, распакуйте новую отдельно и при необходимости скопируйте connection.json. Старые логи переносить не нужно. Не запускайте две копии с одной конфигурацией и общими файлами.

Диагностика JSON содержит сборку, конфигурацию, мастера, состояния устройств, ошибки, очередь и очистку. Полный трафик JSONL доступен только пока есть дисковый журнал; после очистки он пуст. Для расследования скачайте данные до «Отключить оба» и до успешной очистки.

В GitHub Issue укажите модели, прошивку, ОС, Python, последовательность отключения/возврата, мастера и очередь. Прежде чем публиковать JSON, проверьте IP, пути и данные шоу. [Таблица ошибок](TROUBLESHOOTING_RU.md) поможет с первичной проверкой.

## 14. Командная строка

macOS:

~~~sh
python3 allen_heath_dlive_full_mirroring.py --ui-port 8780
python3 allen_heath_dlive_full_mirroring.py --no-browser
python3 allen_heath_dlive_full_mirroring.py --config ./connection.json
~~~

Windows:

~~~powershell
py -3 allen_heath_dlive_full_mirroring.py --ui-port 8780
py -3 allen_heath_dlive_full_mirroring.py --no-browser
py -3 allen_heath_dlive_full_mirroring.py --config .\connection.json
~~~

Если порт 8780 занят, укажите другой, например 8781, и откройте адрес из терминала. Флаг --config меняет только файл конфигурации; порт браузера и адреса устройств — разные вещи.
